```
            │
┌───────────▼───────────────┐        ┌─────────────────────────────────────┐
│  DATABASE                 │        │  CONTENT BANK  (offline, in repo)   │
│  SQLite (dev) → Postgres  │        │  curriculum · item banks · themed   │
│  profiles · interactions  │        │  variants generated by a local LLM  │
│  assignments · outcomes   │        │  then human-reviewed                │
└───────────────────────────┘        └─────────────────────────────────────┘
```

**Content generation never runs at request time.** It is a build-time script whose output
is reviewed and committed. Zero runtime API cost, and generated items can be matched for
difficulty before any child sees them — which the experiment design requires.

## 2. The adaptive loop, step by step

One activity is one turn of the loop.

| # | Step | Who | Notes |
|---|---|---|---|
| 1 | Session starts | API | Loads child profile, builds the day plan |
| 2 | **What to teach** | `SessionPlanner` | Deterministic: mastery gaps + due revisions + educator assignments. **Never randomized** |
| 3 | **How to teach it** | `DecisionEngine` | Exploit the known winner, or explore a matched comparison |
| 4 | Safety check | `DistressMonitor`, `TherapistLocks` | Exploration blocked if distress is rising or the arm is locked |
| 5 | Build `ActivitySpec` | API | A JSON contract the child UI renders (section 6) |
| 6 | Child interacts | Child app | Every touch, timing and attempt is captured locally |
| 7 | Events uploaded | Child app → API | Batched, queued when offline |
| 8 | Immediate outcome | `EffectEstimator` | Correctness, response time, attempts, completion, engagement change |
| 9 | Profile updated | State models | Mastery, retention forecast, interest, modality, engagement |
| 10 | **Delayed outcome** | `RetentionModel` | The same items are re-probed at 3 and 7 days; that result is attributed back to the arm used in step 3 |
| 11 | Drift check | `EffectEstimator` | If a proven winner starts losing, re-open the comparison |

Steps 3, 8 and 10 are the research contribution. Everything else is ordinary app plumbing.

## 3. Module contracts

Each module is a plain Python class with no framework dependencies, so it can be tested
against the simulator in `research/` without a server or a database.

### LearnerModel
```python
get_mastery(child_id, topic_id) -> Mastery(p: float, sd: float, n_trials: int)
update(child_id, interaction) -> None
```
Phase 1: Bayesian knowledge tracing per topic (Beta posterior over skill).
Later: deep knowledge tracing.

### DifficultyModel
```python
next_level(child_id, topic_id, recent: list[Interaction]) -> int           # 1..5
target_success_rate(child_id) -> float   # personalised later; 0.8 initially
```
Phase 1: rules over accuracy, response time, attempts, hints.
Later: the success-rate target itself becomes an experiment axis.

### RetentionModel
```python
retention(child_id, topic_id, at: datetime) -> float          # 0..1 estimate
due_for_revision(child_id, limit: int) -> list[TopicDue]
schedule_probe(child_id, topic_id, delay_days: int) -> None   # 3 and 7 day probes
```
Phase 1: half-life regression, validated first on the public Anki datasets.
Later: neural forgetting model over irregular schedules.

### InterestModel
```python
theme_effect(child_id, theme_id) -> Effect(mean: float, ci: tuple[float, float])
rank_themes(child_id) -> list[ThemeScore]
```
**Estimated only from randomized theme assignments** on matched items — never from
raw selection counts, which are confounded.

### EngagementModel
```python
state(child_id, session_id, window_s: int = 60) -> Literal["high","stable","declining"]
distress_signal(child_id, session_id) -> float   # 0..1, feeds the safety layer
```
Phase 1: rules over latency trend, inactivity, abandonment, error bursts, tap-rate change.
Later: a sequence network (TCN/GRU) over the interaction trace.
Output is an **estimate**, never a diagnosis.

### InterventionModel
```python
candidates(child_id, context) -> list[InterventionArm]
record_outcome(child_id, intervention_id, engagement_delta_60s) -> None
```
Interventions last 5–20 seconds and are themselves an experiment axis.

### ExperimentManager ⭐
```python
active_axes(child_id) -> list[Axis]                       # at most 2 at a time
matched_item_sets(topic_id, n_arms: int) -> list[ItemSet] # equal difficulty and length
assign(child_id, axis, context) -> Assignment             # arm + seed + policy version
```
Matching rules and stopping rules live in `EXPERIMENT-DESIGN.md` (Phase 4).

### EffectEstimator ⭐
```python
posterior(child_id, axis, arm) -> Posterior                # Beta-Binomial + hierarchical prior
winner(child_id, axis) -> Verdict | None                   # None until evidence suffices
predict_winner_early(child_id, axis) -> Verdict | None     # learning-curve forecast
drift_detected(child_id, axis) -> bool
```

### DecisionEngine ⭐
```python
decide(state: ChildState) -> Action
```
Pseudocode:
```
topic      = SessionPlanner.next_topic(state)          # deterministic
axes       = ExperimentManager.active_axes(child)
for axis in axes:
    if TherapistLocks.locked(child, axis):      use locked option
    elif DistressMonitor.rising(state):         use safest known option
    elif EffectEstimator.winner(child, axis):   exploit it
    elif ExplorationBudget.available(state):    explore via Thompson sampling
    else:                                       use current best guess
return ActivitySpec(topic, method, modality, theme, difficulty, probes)
```

### GenAIContentEngine (build time only)
```python
generate_variants(topic_id, theme_id, n: int) -> list[Item]   # offline script
check_item(item) -> list[Violation]   # reading level, length, idioms, banned content
```
Every generated item is human-reviewed before it enters the bank.

## 4. Deterministic vs ML vs GenAI

| Decision | Phase 1 | Research version | Never |
|---|---|---|---|
| What to teach next | rules (mastery + due revision + educator) | knowledge tracing informs priority | not randomized |
| How to teach (method) | random among allowed arms | Thompson sampling + early predictor | — |
| Interaction modality | random among allowed arms | same | — |
| Theme | random on matched items | effect estimate | not from click counts |
| Difficulty | rules | learned per-child target | — |
| When to revise | spaced repetition formula | learned forgetting model | — |
| Engagement state | rules | sequence model | never a diagnosis |
| Which intervention | round-robin | contextual bandit | never hard-coded per child |
| Session length | rule on engagement decay | learned stop rule | never a clinical claim |
| Content wording | template | pre-generated bank | never generated live |

## 5. Data flow

**Immediate path (every few seconds)**
```
child touch → local event buffer → batch POST /events
   → interaction row → LearnerModel, EngagementModel, DifficultyModel updated
   → EffectEstimator gets the immediate outcome for the active assignment
```

**Delayed path (days later) — the part most systems skip**
```
activity completed → RetentionModel.schedule_probe(+3d, +7d)
   → probe appears inside a normal future session
   → probe result → EffectEstimator.attribute(assignment_id, delayed_outcome)
   → posteriors updated → winner may change
```

**Audit path (keeps the model honest)**
```
occasional random re-test of a "mastered" topic, independent of model confidence
   → prevents the system from believing its own optimism
```

## 6. How the child UI changes — the `ActivitySpec` contract

The backend never sends "screen 4". It sends a **specification**, and the child app
renders it. This is what makes *same curriculum, different journey* real.

```jsonc
{
  "activity_id": "a_8f21",
  "assignment_id": "as_44c1",          // links everything back to the experiment
  "topic": { "id": "num_1_5", "label": "Numbers 1–5" },
  "difficulty": 2,
  "method": "errorless",               // errorless | try_then_correct
  "modality": "drag_drop",             // tap | drag_drop | match | flashcard | voice
  "theme": { "id": "dino", "guide": "rex", "assets": "themes/dino" },
  "prompt": { "audio": "how_many_dinos", "text": "How many?", "show_text": false },
  "items": [ { "id": "i_1", "answer": 3, "distractors": [2, 4] } ],
  "hints": { "type": "highlight", "fade_after": 2, "delay_ms": 4000 },
  "feedback": { "correct": "celebrate_small", "incorrect": "gentle_retry" },
  "probes": [ { "kind": "retention", "topic": "num_1_3", "due": "3d" } ],
  "ui": {
    "text_amount": "minimal",          // minimal | some
    "animation": "low",                // low | normal
    "visual_complexity": "low",
    "audio": true,
    "reward_style": "sticker"
  },
  "session": { "planned_minutes": 12, "elapsed_minutes": 4 }
}
```

Rules:
- The app renders whatever it is given and **reports back**; it makes no adaptation decisions.
- Every field that varies is either a locked setting or an experiment arm, and both are
  recorded in `assignments`.
- Unknown fields are ignored, so the spec can grow without breaking older builds.

## 8. Offline and reliability

School tablets lose Wi-Fi. The child app must not stall.

- The next 2–3 `ActivitySpec`s are prefetched and cached.
- Events are written to a local queue and uploaded with retry; every event carries a
  client-generated UUID so replays are idempotent.
- If the queue cannot flush, the session still runs on the cached specs and syncs later.
- Clock skew: the server stamps `server_time`; the client sends `device_time` and
  monotonic offsets so response times stay trustworthy.

## 9. Privacy and safety in the architecture

- **Camera is off by default**, requires explicit guardian consent, can be revoked, and
  has a permanent no-camera mode. If used, frames are processed and discarded; only
  derived low-dimensional signals may be stored.
- Minimal personal data: first name or nickname, age band, guardian contact. No address,
  no school ID in the research export.
- The research export is pseudonymous (`child_hash`), and consent state is checked before
  any export.
- The distress budget is enforced in the engine, not in the UI, so no client bug can
  bypass it.
- Every automated decision is auditable: policy version, seed, inputs and the alternatives
  considered are all stored.

## 10. Non-goals

Not an LMS. Not a diagnostic tool. Not a therapy replacement. No live LLM in the child
loop. No claim that AURA measures emotion, intelligence or attention span.
